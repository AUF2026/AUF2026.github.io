0. Governing rule

This registry records candidate Faure theorems generated by structural synthesis of the existing AUF2026 corpus.

A candidate is not considered a verified theorem merely because:

it is suggested by an existing document;

it follows informally from a documented genealogy;

a numerical example supports it;

an existing Lean file contains related declarations;

a previous manuscript calls it a theorem.

Promotion to FORMALLY VERIFIED requires a dedicated formal artifact and an actual successful Lean verification record.

The governing verification chain is:

EXISTING CORPUS
      ↓
EXACT MATHEMATICAL PROPOSITION
      ↓
CLASSICAL FORMALIZATION
      ↓
LOGICAL FORMALIZATION
      ↓
LEAN 4 FORMALIZATION
      ↓
KERNEL VERIFICATION
      ↓
LATEX / TEXSTUDIO
      ↓
VALIDATION RECORD
      ↓
PUBLIC ARCHIVE


Required completed Lean state:

SORRY_COUNT  = 0
ERROR_COUNT  = 0


Warnings must also be recorded rather than silently ignored.

The following identifiers are internal candidate identifiers.

They are intentionally written as:

rather than immediately assigning public theorem numbers.

The public names and final theorem numbering Faure Theorem I, Faure Theorem II, ..., must be frozen only after the complete existing theorem registry I–XV and all other already-existing theorem identifiers have been reconciled.

This prevents accidental duplication or renumbering of an existing theorem.

14. Promotion protocol

A candidate can progress only through the following states:

CANDIDATE
   ↓
EXACT STATEMENT EXTRACTED
   ↓
CLASSICAL PROOF ESTABLISHED
   ↓
LOGICAL FORMALIZATION ESTABLISHED
   ↓
LEAN FORMALIZATION WRITTEN
   ↓
LEAN VERIFIED
   ↓
LATEX VERIFIED
   ↓
VALIDATION RECORD COMPLETE
   ↓
FORMALLY VERIFIED


No state may be skipped.

In particular:

Lean file exists ≠ Lean proof verified
Lean proof verified ≠ scientific claim validated
Mathematical proof ≠ originality established
Originality ≠ external acceptance
